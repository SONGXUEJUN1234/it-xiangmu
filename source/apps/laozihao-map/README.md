# 老字号地图

一个可运行的独立中文网页原型：在地图上按地区和品类发现老字号，查看简短介绍，并前往经过核验的网店。已按商务部名录（2025年12月版）全量收录 1450 项品牌，其中 30 个为详细整理的精选档案。电脑端地图与品牌列表联动，手机端可切换地图与列表。

**这是探索原型，不是已完成合规核查的正式上线产品。** 不改动 `weixin` 或其他既有项目，不需要数据库、账号或地图 API Key。

## 本地运行

建议 Node.js 22 或更高版本。

```sh
npm ci
npm run dev
```

打开终端给出的本地地址，默认 `http://localhost:5173`。开发服务器绑定 `0.0.0.0`，仅应在可信开发网络中使用。

```sh
npm test           # 40 项数据、导入、安全与地图聚合测试
npm run build      # TypeScript 检查及生产构建
npm run preview    # 本地预览构建结果，默认 4173 端口
```

压缩包中包含 `dist/`，可在完成上线检查后放到支持静态文件的服务器。**不能直接双击 `index.html` 运行**，JSON 数据需要通过 HTTP 读取。当前资源路径按域名根目录部署设计，子路径部署需要修改 Vite base 和数据/字体资源路径。

## 已实现

- 全国行政区示意地图，支持点击省份、缩放、拖动和重置。
- 全国省级聚合、选省后城市级展示；按屏幕距离再次聚合重叠点，手机端保持 40px 点击区域。点击跨地区聚合点逐级展开，点击省份直接筛选。
- 分类、省份、城市、搜索与“仅看可网购”组合筛选；搜索支持特色产品与多个关键词。
- 地图和品牌列表联动、卡片网格、排序、空结果提示；全量列表分批「加载更多」。
- 品牌详情、来源折叠区、网店跳转（区分官方核验与平台核验）、官网与网购入口区分。
- URL 保存筛选与当前品牌，刷新后保留状态。
- 手机地图/列表切换、底部详情弹窗；键盘可操作，弹窗使用原生 dialog 管理焦点与 Escape。
- 本地数据工作台：JSON 编辑、CSV/JSON 导入预览与确认、导出、恢复默认数据。
- 本地纠错草稿、导出、处理后删除。
- 字体、底图、初始资料和原创插画随项目附带，核心展示无需实时第三方请求。点击来源或网店才访问外部网站；导入的远程品牌图片需要网络。

## 当前资料边界

| 项目 | 当前状态 |
| --- | --- |
| 品牌 | 商务部《中华老字号名单》（2025年12月版）全量 1450 项；其中 30 个精选档案含详细资料 |
| 网购入口 | 两级核验：官方来源指向（品牌官网等权威页外链）与店铺页自证（天猫旗舰店标题含品牌名，逐店核验） |
| 认定依据 | 商务部公共服务资源平台名录（2025-12-01）；2026 年新一轮复核结果公布后需更新 |
| 位置 | 省市行政区中心，用于归属地示意，不是门店地址；名录未提供城市的条目按省级展示 |
| 品牌照片 | 尚未填写授权实拍；使用明确标注的原创品类插画 |
| 品类标签 | 精选 30 个逐条人工归类；全量条目按企业名称关键词初步归类，待逐条核实 |
| 下单、库存、配送 | 未验证；第三方可能要求登录或使用 App |
| 数据修改、纠错 | 只存当前浏览器，不上传服务器、不跨设备同步 |
| 部署 | 本地开发预览；未购买域名、未公开部署 |

名录按地区排序、区内不分先后；青岛、宁波、大连、厦门、深圳五个计划单列市条目并入所属省份展示。26 项名录未单列品牌名的条目，以人工核定的企业字号作为品牌名并在依据中注明。品牌图片和品牌资质的核验是两个独立事项，图片存在不代表资料完整。

## 数据维护

在页面右上角打开“数据工作台”。

1. 先导出 JSON 或 CSV 备份。
2. 下载表格模板，在电子表格中编辑。CSV 的 `categories`、`specialties` 用 `|` 分隔；`sources`、`shop`、`image` 是 JSON 字符串。空的 `shop`/`website`/`image` 表示待补充。
3. 导入时先进行格式检查，再显示替换预览；确认后才覆盖本地品牌数据。
4. 少量变更可选择品牌修改 JSON，不能直接更改该条 ID。新增品牌使用完整表格导入。
5. 数据工作台会检查字段、HTTP(S) URL、日期、省市、重复 ID。**格式通过不等于已核实店铺授权或图片许可，仍需人工审核。**
6. 正式更新内置资料时，用审核后的 JSON 替换 `public/data/brands.json`，然后测试、构建。浏览器若有本地覆盖，需要“恢复内置首批数据”才能看到新的内置版本。

本地存储键：

- `laozihao-map.brands.v1`：完整品牌覆盖数据。
- `laozihao-map.corrections.v1`：纠错草稿。

数据工作台是本机编辑工具，不是有权限控制的线上管理后台。切勿在此存放个人联系方式、支付数据或其他机密资料。存储空间不足或被浏览器禁用时，界面报告错误，不会宣称保存成功。

## 项目结构

```text
src/App.tsx               页面、筛选、URL 和本地状态
src/HeritageMap.tsx       SVG 地图投影、缩放、拖动及标记
src/mapUtils.ts           屏幕距离聚合逻辑
src/Dialogs.tsx           详情、说明、纠错及本地数据工作台
src/Art.tsx               原创 SVG 插画及真实图片回退
src/model.ts              数据模型、校验、搜索和 CSV 转换
src/styles.css            视觉与响应式样式
src/accessibility.css     对比度和字号调整
public/data/brands.json   带来源的首批资料
public/data/regions.json  地区、城市中心点及来源
public/data/china.geojson 预览底图，保留原始全部 35 个要素
public/fonts/             Noto CJK 字体子集及许可
```

更多资料来源与上线条件见 [DATA-SOURCES.md](DATA-SOURCES.md)；测试记录见 [TESTING.md](TESTING.md)。

## 下一阶段

1. 跟踪商务部 2026 年复核结果（汇总表 2026-09-30 前报送）与第四批认定，及时更新名录基础表。不要把一份名单当作永久有效名单。
2. 逐步把平台自证网店升级为官方来源核验；复核存量链接的店铺主体与授权。
3. 获得品牌图片授权；编辑 `image` 时填写图片地址、说明、来源与许可。不要抓取没有使用许可的网店图片。
4. 逐条核实全量条目的品类与城市归属，替换关键词初步归类。
5. 根据真实使用场景选择合规地图服务或已核验许可的底图，并完成边界、审图及互联网地图服务要求核查。
6. 正式公开导购前，单独核查医药内容及跳转、商标标识使用、网站备案和隐私要求。
7. 有多人维护需求时，再增加数据库、身份验证、审核队列及链接巡检任务。
